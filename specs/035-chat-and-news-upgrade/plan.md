# Implementation Plan: Chat AI & News Platform Upgrade

**Branch**: `035-chat-and-news-upgrade` | **Date**: 2026-08-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/035-chat-and-news-upgrade/spec.md`

## Summary

Six changes, three of them sharing one backbone: a new queryable `news_articles`
collection.

1. **News becomes real data.** A new `market_news_pull` admin job (already
   reserved in 017's registry table but never implemented) ingests three FMP
   feeds — general market news, FMP editorial articles, and stock-specific news
   — into a `news_articles` collection keyed by source URL, with a 30-day
   backfill paced inside the existing FMP budget guard.
2. **Chat can read it.** The semantic layer becomes multi-collection: a
   `NEWS_SCHEMA` joins `SCREENER_SCHEMA`, `query_guard.READABLE_COLLECTIONS`
   admits `news_articles`, and `chat.py` executes against the collection the
   model actually chose (today it validates `collection` and then hardcodes
   `db[SCREENER]` — a latent bug that goes live the moment a second collection
   is readable).
3. **The semantic model gets verbose.** Each field gains `unit`, `enum`, and
   `aggregation` hints, and the system prompt gains worked few-shot pipelines
   including a `$group` example — directly addressing "I don't think it's
   always doing that" for aggregation-shaped questions.
4. **Answers become navigable.** A deterministic post-processing step rewrites
   recognized tickers into `[NVDA](/stock/NVDA)` markdown before the answer is
   returned or stored, and `AnswerText` learns to route root-relative hrefs
   through react-router instead of a new browser tab. News citations reuse the
   same mechanism with external URLs.
5. **Chat history persists.** A `chat_conversations` collection plus four
   endpoints, with the conversation title generated by one extra LLM call after
   the first exchange only.
6. **Sidebar consolidation.** `Sidebar.tsx` grows a second, independently
   scrollable Top Traded Stocks section; `MostActivesPanel` is removed from the
   Stocks page.

The deliberate architectural choice throughout: news retrieval rides the
*existing* LLM query-generation path (one call, model picks the collection)
rather than adding a third intent-classifier call in front of every question.
See [research.md](research.md) R2.

## Technical Context

**Language/Version**: Python 3.12 (backend + agent-runner), TypeScript 5.6 / React 18 (frontend)

**Primary Dependencies**: FastAPI, Pydantic v2, PyMongo (sync), Ollama (`qwen3:14b`), React 18 + Vite 5, TanStack Query v5, react-markdown 10, Tailwind v4. **New**: `rehype-raw` + `rehype-sanitize` (frontend, news body HTML only); no new backend runtime dependencies (HTML→text stripping uses stdlib `html.parser`).

**Storage**: MongoDB 7.x — two new collections (`news_articles`, `chat_conversations`), no schema migration to existing ones.

**Testing**: pytest (backend, agent-runner), Vitest + React Testing Library (frontend). Cross-service field-vocabulary contract mirrored per constitution VI.

**Target Platform**: Self-hosted Docker Compose stack, single user, local-first.

**Project Type**: Web application — `backend/` (FastAPI) + `frontend/` (React SPA) + `agent-runner/` (queue worker), three separate images.

**Performance Goals**: Chat answer within the existing ~10s target inherited from 031 SC-001 — news questions must not add a second intent-detection LLM call. News tab renders within the existing market-news freshness contract (60-minute refresh window).

**Constraints**: FMP daily soft cap (250/day) is a hard operational ceiling — the 30-day backfill MUST be resumable across days rather than a single burst. MongoDB auth is not enabled, so `query_guard`'s allowlist remains the only read-only enforcement and must be extended, not bypassed, for the second collection.

**Scale/Scope**: ~8,340 screener docs today; news at 3 feeds × 30-day backfill ≈ low tens of thousands of articles, single-user read volume. 6 user stories, ~2 new backend routers' worth of endpoints, 2 new collections, 1 new agent-runner job.

### Post-design re-check against constitution v1.1.0

Principle VI was amended mid-planning to extend cross-layer consistency to the
semantic layer: any collection in `query_guard.READABLE_COLLECTIONS` must carry
a mirrored field-vocabulary contract test in **both** services, and every schema
field must carry a type and a model-usable description.

This feature is the first to be planned under that rule, and it is the change
that admits the second-ever collection to `READABLE_COLLECTIONS`. The design
already satisfied it by construction — [contracts/news-collection.md](contracts/news-collection.md)
specifies exactly the mirrored pair the amended principle now mandates — so the
amendment tightened the rule without invalidating any design decision here.

Two obligations the amendment makes explicit, both already in scope:

- `backend/tests/test_news_contract.py` and
  `agent-runner/tests/test_news_contract.py` are **required**, not optional —
  admitting `news_articles` to `READABLE_COLLECTIONS` without them is now an
  incomplete change by constitutional definition.
- Every `NEWS_SCHEMA` field needs a type and a description good enough for the
  model to use it correctly — the same bar `test_screener_contract.py:31`
  already enforces for `screener`, now applied to news.

**Re-check result: PASS.**

Two constitution-relevant notes carried into design:

- **Frontend deps**: adding `rehype-raw` + `rehype-sanitize` is a stack addition
  under the Technology Stack Constraints clause. Justified in
  [research.md](research.md) R8 and recorded here rather than silently taken:
  FR-006a requires rendering source HTML formatting, which the current
  deliberately-inert markdown pipeline cannot do. `AnswerText` keeps its
  no-`rehype-raw` guarantee from 034 untouched; the new plugins are scoped to a
  separate `NewsBody` component.
- **Latent bug fixed, not worked around**: `semantic/chat.py:143` hardcodes
  `db[SCREENER]` while honoring a validated `collection` variable. Unreachable
  today, live the moment `READABLE_COLLECTIONS` grows. Fixing it is in scope.
